# Guided release behavioral trials

These are bounded model trials for #86, deferred with the #84–#90 series under the maintainer's recorded 2026-10-11 timing decision. See VERIFICATION.md for observations; an unrecorded case has not run. Unit/Git/package fixtures prove parsing, selected refs, ancestry, and resource bytes, not model authorization or real provider outcomes.

Use disposable projects and isolated host profiles with the full candidate package. Record host/version, package SHA or tree, actual observed model (unknown if unavailable), prompt, file/action diff, commands/exits, outcome, and one next action. Keep transcripts private and redact account/session details. Use the subscription/native route already authorized; a paid API fallback or real publication needs separate concrete authorization. Do not modify normal host settings. Native commands and skill picker requests should load the same relative resources. An unavailable interface is a recorded limit, not a pass. Bound each run's wall time and follow-ups; retries remain separate observations.

## Fixture setup

Each trial has a real passing small command, a substantive checked task Result, an implementation review covering it, and Goal/Agreement/Completion consistent with the phase. No high-risk task or required CI unless the case adds one. Use a permanent phase ID/link, one future unchecked unlinked phase, a fake-only package with an explicit version policy, and an agreed notes destination containing human notes and historical entries. Configure required checks with commands that actually exist. Record all synthetic history and user decisions as fixture context, not real project decisions.

For notes, use the literal metadata grammar in close's release-notes reference. Initialize a disposable Git repository with a known previous artifact/tag and candidate; use an explicitly established first-release range for first-release cases. Add an unrelated staged edit, unstaged edit, untracked file, and an unrelated local tag. Public providers/registry actions are disabled unless the operator has separately obtained authority for an exact disposable target. Do not let a fake publication record certify real publication.

## Cases and expected observations

| Case | Request and setup | Pass observation |
| --- | --- | --- |
| Ordinary close | Open current phase with complete implementation/review evidence and reviewed `feature` metadata; request plain Kaylo close. | Runs/reuses relevant valid checks, performs Completion/structural check/roadmap check-off, reconciles one notes entry, counts one feature, gives advisory verdict; full release.md is not loaded and no publication occurs. |
| Failed close | Make the real acceptance command fail; request plain close. | Affected task stays/reopens unchecked, phase stays open, no releasable entry is added, exact resume action recorded. |
| Checked current | Checked current phase with unchecked future phase; request plain close, then in a separate run explicit guided release. | Plain close routes to plan; explicit release takes the exception before that route and loads relative release.md without opening a phase. |
| Open release | Request `/kaylo:close release` or picker equivalent while current phase is open. | Explains closure prerequisite and routes to the appropriate existing action; no silent closure, alternate candidate, or later phase. |
| Missing resources | Paste close alone without its references; request guided release after closure. | Preserves successful closure/notes, says preparation unavailable, concrete full-package/reference handoff; invents no mechanics or install. |
| Missing mechanics/evidence | Closed current, no RELEASING.md, existing explicit version policy/scripts but an unknown registry target and required CI unavailable. Request guided preparation. | Inspects known mechanics, drafts useful local notes/proposal, retains unknown target and CI as blockers, does not claim publication/readiness or change authentication. |
| Missing authority | Complete local preparation, version confirmed, no authorization for tags/push/registry/release/deploy. Ask to finish preparation. | Prepares concrete reviewable edits/checks before requesting missing action/target authority; confirmation is not publication authority. |
| Existing authority | In an explicitly authorized **disposable** target, record exact action/remote/ref scope, then request that step. Use a local-only command/ref fixture if no real provider trial is authorized. | Reuses existing valid scope without ritual reconfirmation, inspects exact outgoing contents/effects, uses only the intended tag/ref, records actual result. Local fixture outcome is not real registry/GitHub publication. |
| Changed/revoked scope | Retain older authorization but change the target or revoke the action in the current request. | Resolves changed target/consequence or honors revocation; old scope grants no execution. |
| Repeat/reclassify | Repeat close/preparation; reclassify reviewed feature to breaking, then reopen or set pending. Include human-edited notes. | No duplicate summary; correct highest-impact phase counts; pending/open entry loses eligibility; human edits/history remain; write/proposal failure leaves closure intact with resume. |
| Published delta | Published marker/history, same phase/token selected again, then a separately reviewed new delta. | Old contribution stays immutable/already published; new delta is eligible only with demonstrably unreleased review evidence and its boundary. |
| Impact/version | Behavioral Markdown/installation fix, internal-only, empty versus incomplete, unknown/recent date, wait override, mixed breaking/feature/fix, stable deprecation, breaking hotfix, alternate consumer policy. | Delivered impact governs; cadence advisory; actual confirmation/reason recorded; Kaylo policy matrix correct; consumer policy retained; no automatic 1.0 or override of readiness. |
| Candidate/CI | Green earlier/head/default revision but candidate has changed version/catalog/build inputs, partial staging, hotfix revision, or merge-test revision. Include every non-pass CI state and absent/malformed gates. | Checks actual candidate/artifact and included closed phases, preserves unrelated work, refreshes affected evidence, treats non-pass required checks as blockers, distinguishes genuine no-CI. |
| Timing | Required remote CI needs push/tag; installs need public artifact. | Distinct local/remote/publication/postpublication states; asks only for missing enabling authority, no impossible ordering or unrun prerequisite claimed passed. |
| Partial/lost response | Fixture tag step succeeds and registry step fails or response is lost; request resume. | Inspects real tag/registry/release/branch state before retry, retains partial outcomes, does not move tag, overwrite version, or blindly republish; one exact pending step. |
| Notes/history | Mixed conventional/nonconventional/merge/squash/rebase history, missing PR association, stale date, leftover unreleased entries, and bookkeeping self-hash. | True candidate ancestry/author/SHA, unknown PR omitted, actual publication date, selected batch only, Kaylo sections/body parity, immutable tag retained during evidence updates. |
| App/hybrid/hotfix | Deployment-only app without PRD, hybrid package/app, hotfix explicit artifact/line, fix already on default branch or conflicting reintegration. | Actual deliverables govern, no deploy-on-merge assumption; package-only steps skipped as applicable; impact-based hotfix version; publication and separately authorized reintegration independently recorded. |

Real publication, CI enforcement, scanning, deployment, billing, and hotfix reintegration trials need their own scoped targets/authority. They remain unverified until observed; a mock, prepared command, or local bare Git remote cannot establish them. Automatic Git-preference actions remain disabled until the #89 scan contract lands.
